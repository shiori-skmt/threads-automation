# Threads(@shibainu_yuzu__) 朝の挨拶投稿パイプライン(毎朝6時投稿・PR/つぶやきとは別枠)

このファイルは、スケジュール実行されるClaude Codeセッションが**会話の記憶を一切持たない状態**で読む指示書です。`/Users/shiori/Claude/Threads/rakuten-threads-bot/MORNING_GREETING.md` の構成をこのアカウント用に調整したもの。

作業ディレクトリ: このリポジトリの `shibainu-yuzu-bot/` フォルダ(相対パスで扱う)

この投稿は「おはようございます」+前向きな一言(たまに小さなTips)という、`PIPELINE.md` のPR型・つぶやき型とは別枠の固定コンテンツ。商品紹介やアフィリエイトは一切含めない。

**投稿は6時に自動で行いたいが、内容の確認はユーザーが仕事中の時間帯(前日15時頃)に行いたい**、という運用のため、3つの独立したスケジュールタスクに分かれている:

- **タスクA(毎日15:00実行)**: 翌朝分のドラフトを作成し、チャットに提示して承認を待つ。**投稿はしない**
- **タスクC(毎晩23:00実行)**: タスクAのドラフトがまだ未承認なら、寝る前に一度だけリマインドする。**新規に文章を作らない。投稿もしない**
- **タスクB(毎朝6:00実行)**: 承認済みの「今日分」ドラフトがあれば、それをThreadsに投稿する。未承認なら見送ったことをユーザーに知らせる。**新規に文章を作らない**

## ペルソナ(`PIPELINE.md` 2節と共通)

黒柴「ゆず」(2022.1.23生まれ)と暮らす飼い主。東京都世田谷区在住。2026.7.25に左目の緑内障を発症、治療費のためこのアカウントを運営中(フォロワーには公表済み)。一人称は「私」、二人称「あなた」は使わない。猫の同居なし、南魚沼生活は過去の期間限定エピソードなので持ち出さない。

**「今日」「翌朝分」などの日付は、すべて日本時間(JST, UTC+9)基準で決めること(必須)。** クラウド環境はUTCで動くため、生の日付をそのまま使うとJST早朝(0〜9時台)は前日扱いになってしまう(検証済みの不具合)。作業開始時に一度、次のコマンドでJST日付を取得し、以降の日付計算はすべてこの値を基準にする:
```bash
TZ=Asia/Tokyo date +%Y-%m-%d
```

**状態の永続化(git pull/push、必須)**: 作業開始時に必ず `git pull` してから読み始めること。`state/` 配下を1つでも変更したら、その都度リポジトリのルートで `git add shibainu-yuzu-bot/state && git commit -m "update state: ..."`、続けて `git pull --rebase`、`git push` を実行する(push失敗時はpull --rebase後に再push)。

## 状態管理フォルダ

- `state/morning_greeting/pending/{YYYY-MM-DD}.md`: 承認待ちドラフト(ファイル名の日付 = 投稿予定日)
- `state/morning_greeting/approved/{YYYY-MM-DD}.md`: 承認済み・投稿待ち
- `state/morning_greeting/posted/{YYYY-MM-DD}.md`: 投稿済みアーカイブ

## タスクA: ドラフト作成(毎日15:00実行、投稿はしない)

1. 対象日(投稿予定日)を「実行日の翌日」の日付(YYYY-MM-DD)とする
2. `state/morning_greeting/pending/{対象日}.md` または `approved/{対象日}.md` が既に存在する場合、何もせず終了する
3. 内容を作る:
   - ベースは「おはよう」の一言+前向きな気持ち(ゆずとの朝の実感、柴犬らしい仕草など)
   - **天気・季節ネタにする場合は、投稿前に必ず東京の実際の天気を確認し、内容と齟齬が無いようにする**(例: `curl -s "https://api.open-meteo.com/v1/forecast?latitude=35.6895&longitude=139.6917&current_weather=true"`)。確認できない/合わない場合はこのテーマを避ける
   - 約4回に1回程度(25%程度)の頻度で、末尾に小さなTipsを添える。Tipsは柴犬・犬全般のお世話のちょっとしたコツで、**商品名・ブランド名・アフィリエイトリンクは一切含めない**
   - ごく稀に(頻度は控えめ、毎回ではない)、緑内障との付き合い方や応援への感謝に軽く触れてもよいが、深刻になりすぎないこと
   - 基本は1投稿で書き切る
4. **厳守事項**: 商品名・ブランド名・アフィリエイトリンクを一切含めない。「PR」「#PR」表記を付けない。購入や来店を促す表現を使わない
5. **自然さのルール**: 二人称「あなた」を使わない。ゆずの反応を作り話っぽく足さない。**文末には必ず絵文字か記号(「…」「〜」「!」「?」)を入れる**(何もつけずに終わらせない)。比率の目安は絵文字7割・記号3割程度。**改行・空行は、同じ話の流れ(同じ出来事の続き)はまとめて改行のみ、別の出来事・場面に移るところにだけ空行を入れる**(1文ごとに機械的に空行を入れない)。**空行の後は「そういえば」「あ、」「でもさ」のような自然な接続語を添える**(毎回同じ言葉を使い回さない)
6. **人間らしさのルール(`PIPELINE.md` 8節と共通)**: 説明しすぎない/文の長さを揃えない/抽象的な言い回しを避け具体的に語る/綺麗にまとめすぎない。**書き終えたら「AIっぽい」語尾・言葉選びだけを抽出して人間らしく直す推敲パスを必ず行う**
7. チェッカー: 商品名・リンク・PR表記が無いか/購入を促す表現が無いか/薬機法・景品表示法に抵触しないか/500字以内か/二人称「あなた」を使っていないか/ゆずの反応が作り話っぽくないか/緑内障の話題が重すぎないか/推敲パスを通したか/文末が毎回絵文字か記号で終わり絵文字7割・記号3割程度の比率か/各空行が本当に別の出来事・場面への切り替わりか(実際に1つずつ検討する)/空行の直後に自然な前置きがあるか、を全て満たすまで書き直す
8. `state/morning_greeting/pending/{対象日}.md` に保存する(投稿予定日・本文・Tipsの有無を明記)
9. ユーザーにチャットで内容をそのまま提示し、「これでOKか、修正したい点はあるか」を尋ねて**このセッションは終了する(絶対に投稿しない)**

## タスクC: 前夜リマインド(毎晩23:00実行、新規作成・投稿はしない)

**このタスクはあいさつ投稿(このファイル)専用。** 昼枠・夕方枠(`PIPELINE.md`)は別の時刻(昼枠11:00/夕方枠17:00)に専用のリマインドタスクがある。

1. 明日の日付(実行日の翌日、YYYY-MM-DD)を対象日とする
2. `state/morning_greeting/approved/{対象日}.md` が既に存在する場合、何もせず静かに終了する
3. `state/morning_greeting/pending/{対象日}.md` が存在する場合、その本文をチャットに再掲し、「明日の朝6時に投稿されるあいさつ文です。寝る前にOKをもらえますか?」と一言添えてリマインドする
4. `state/morning_greeting/pending/{対象日}.md` も存在しない場合、その旨を簡潔にユーザーに知らせる

## タスクB: 投稿(毎朝6:00実行)

1. 今日の日付(YYYY-MM-DD)に一致するファイルが `state/morning_greeting/approved/` にあるか確認する
2. **無ければ**、`state/morning_greeting/pending/{今日の日付}.md` が残っていないか確認し、見送りを知らせて終了する
3. あれば、PIPELINE.mdの「0. 認証情報の読み込み」と同様にプロンプト中の認証情報をexportした上で、Threads Publishing APIでテキストのみの単独投稿をする。
   ```
   POST https://graph.threads.com/v1.0/{THREADS_USER_ID}/threads
     ?media_type=TEXT&text={本文}&access_token={THREADS_ACCESS_TOKEN}
   ```
   → 同様に `threads_publish` で公開
4. 投稿成功後、`state/morning_greeting/approved/{今日の日付}.md` を `state/morning_greeting/posted/{今日の日付}.md` に移動する
5. ユーザーに一言報告する
6. 投稿に失敗した場合、ユーザーにエラー内容を報告する

## 承認後のキュー登録(ユーザーがタスクAのドラフトにOKを出した時に実行)

1. 修正指示があれば、それを反映してから進める
2. `state/morning_greeting/pending/{対象日}.md` を `state/morning_greeting/approved/{対象日}.md` に移動する
3. ユーザーに「{対象日}の朝6時に投稿されるようキューに登録しました」と報告する。**この時点でも投稿はしない**
